void greetuser(/* name data at ebp+8 */)
{
    char greeting[72];    // at ebp-0x48

    // Copy greeting prefix based on language global:
    if      (language == 0) memcpy_inline(greeting, "Hello ",         6);  // 7 bytes with null
    else if (language == 1) memcpy_inline(greeting, "Hyvää päivää ", 18);  // 19 bytes with null (Finnish, contains UTF-8 multi-byte chars)
    else if (language == 2) memcpy_inline(greeting, "Goedemiddag! ", 13);  // 14 bytes with null (Dutch)

    strcat(greeting, (char*)(ebp+8));   // ← VULNERABLE: appends name with no bounds check
    puts(greeting);
}

So we have 

[	buf[76]	  ]
argv[1] fills buf[0...39]		MAX 40 bytes
argv[2] fills buf[40..71]		MAX 32 bytes

greetuser(buf)					THEN buf is called

In greetuser a new 72-byte buffer called greeting is created:

greeting = [prefix] + [buf]

prefix depends on LANG:

LANG=nl -> "Goedemiddag! " (13 chars)
LANG=fi -> "Hyvää päivää " (18 chars)
nothing -> "Hello " (6 chars)

The bug is that greeting is only 72 bytes, but nobody checks if prefix + buf 
fits inside it.

Greetuser() calls strcat() and what happens is that after the prefix fills slots 0–12,
strcat starts copying buf into slot 13, 14, 15... all the way up — past slot 71, with 
no stop.

Slot 71 = last byte of greeting buffer
Slot 72 = saved ebp       ← oops, we're writing here now
Slot 76 = return address  ← and here — this is what we hijack

We'll put the shellcode at the beginning of name, which lives at ebp+8 inside greetuser:

argv[1] (40 bytes) = [17× NOP] + [23-byte shellcode]
argv[2] (32 bytes) = [23× padding] + [4-byte ret addr] + [5× padding]
